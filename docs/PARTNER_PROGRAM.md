# Партнёрская программа и промокоды

Решения пользователя от 13 октября 2026. Подписка будет оплачиваться за
пределами Telegram, поэтому программа своя: каждому партнёру выдаётся
промокод, клиент получает его по ссылке или вводит сам, а в базе
остаётся, кто кого привёл.

Оплаты в продукте пока нет. Всё, что от неё не зависит, сделано: учёт
партнёров, промокоды, привязка клиентов, отчёт за месяц. Что появится
вместе с оплатой — в разделе 7.

## 1. Как клиент получает промокод

**По ссылке.** `https://t.me/ИМЯ_БОТА?start=КОД` — Telegram открывает бота
и по кнопке «Старт» присылает боту `/start КОД`. Бот отправляет
«Знакомство» и сразу за ним — сообщение, что промокод применён.
Предложение ввести промокод такому клиенту не приходит.

**Сам, сообщением.** Новому пользователю, который пришёл без промокода,
через 10 секунд после «Знакомства» приходит предложение его ввести (на
деле 10–12 секунд, см. раздел 6). Следующее сообщение человека бот читает
как промокод. Под предложением кнопка «Нет промокода».

**Позже.** Пока промокод ещё можно ввести, в разделе «Подписка 🎁» под
экраном стоит кнопка «Ввести промокод 🎟».

**При оплате** клиенту снова будет предложено ввести промокод — этот шаг
появится вместе с оплатой (раздел 7).

## 2. Правила

- Промокод записывается клиенту **один раз** и не меняется — ни другой
  ссылкой, ни вводом другого кода.
- Скидка по промокоду — **только на первую оплату**. После первой оплаты
  (`users.first_paid_at` заполнен) промокод не принимается, а уже
  записанный больше не даёт скидку.
- Свой собственный промокод применить нельзя. Чужой промокод партнёр
  применить может.
- Регистр не важен: `ivan10`, `Ivan10` и `IVAN10` — один код. Хранится в
  верхнем регистре.
- Промокод — от 3 до 32 символов: латинские буквы, цифры, «_» и «-». Это
  ровно то, что Telegram разрешает в ссылке `?start=…`, поэтому один и
  тот же код годится и для ссылки, и для ввода руками.
- Ссылка с промокодом действует и для того, кто уже пользовался ботом, —
  если промокода у него ещё нет и оплат не было.
- Ссылка с несуществующим, приостановленным или собственным кодом
  работает как обычный «Старт»: без сообщения об ошибке.
- Тем, кто уже пользовался ботом, предложение ввести промокод само не
  приходит — у них есть кнопка в «Подписке».
- Бот ждёт промокод обычным сообщением один час после предложения. Потом
  текст снова понимается как обычно. Нажатие любой кнопки меню ожидание
  не сбрасывает: до истечения часа следующее сообщение, которое не
  является кнопкой меню, всё равно прочитается как промокод.
- Если человек за 10 секунд после «Знакомства» успел начать другой диалог
  (поиск компании, обращение в поддержку), предложение приходит, но этот
  диалог не перебивает: промокод тогда вводится через «Подписку».
- Предложение не отправляется, если бот у человека заблокирован, промокод
  уже записан или оплата уже была.

## 3. Команды администратора

Работают только у администратора (`admin_telegram_id` в
`config/telegram_bot.php`). Остальным бот отвечает «Не понимаю эту
команду».

| Команда | Что делает |
|---|---|
| `/partner @имя КОД` | назначить человеку промокод — сделать его партнёром |
| `/partner @имя КОД 20` | то же и задать процент вознаграждения |
| `/partner @имя НОВЫЙКОД` | сменить промокод партнёра (процент остаётся прежним) |
| `/partner_off @имя` | приостановить: по коду новые клиенты не записываются |
| `/partner_on @имя` | вернуть партнёра |
| `/partners` | итоги за текущий месяц |
| `/partners 2026-10` | итоги за указанный месяц |
| `/partner` | подсказка по командам |

Вместо `@имени` можно указать числовой Telegram ID — для тех, у кого нет
имени пользователя. Партнёром можно назначить только того, кто хотя бы
раз нажал «Старт» в боте: партнёр — это пользователь бота.

В ответ на назначение бот присылает готовую ссылку для клиентов. Чтобы в
ней стояло настоящее имя бота, оно указывается в `config/telegram_bot.php`
строкой `'bot_username' => 'ИмяБота'` (без «@»). Без этой строки ссылка
показывается шаблоном с «ИМЯ_БОТА»; на работу самих ссылок это не влияет.

При смене промокода прежний код перестаёт действовать, а клиенты, которые
им воспользовались, остаются за партнёром. Один и тот же промокод двум
партнёрам выдать нельзя. Смена кода приостановленному партнёру снова
делает его активным.

программа и промокоды». Написаны 13.10.2026, пользователь оставил за собой
правку.

Пока в «Подписке» стоит кнопка «Ввести промокод 🎟», этот экран не несёт
клавиатуру меню (у сообщения может быть только одна клавиатура). Для
значка меню в Telegram Desktop (BOT_UX_SPEC.md, раздел 10.6) остаются
каждое десятое уведомление и команда `/menu`.

## 5. Что хранится

Миграция `database/034_partner_program.sql`.

**`partners`** — кто партнёр. Строки нет — не партнёр.

| Колонка | Смысл |
|---|---|
| `user_id` | пользователь бота (`users.id`) |
| `promo_code` | промокод, в верхнем регистре, уникальный |
| `status` | `active` / `paused` |
| `reward_percent` | процент вознаграждения; `NULL` — не задан |
| `created_at`, `updated_at` | когда назначен и когда менялся |

**`users`** — кто привёл клиента. Первые две колонки есть с миграции 001 и
до сих пор не заполнялись.

| Колонка | Смысл |
|---|---|
| `referred_by_user_id` | партнёр, который привёл клиента (`users.id` партнёра) |
| `used_referral_code` | промокод, которым клиент воспользовался |
| `referral_source` | `link` — пришёл по ссылке, `manual` — ввёл сам (новая) |
| `referred_at` | когда промокод записан (новая) |
| `first_paid_at` | первая оплата; пока пусто — скидка положена (есть с миграции 001) |

`users.own_referral_code` не используется: промокод партнёра лежит в
`partners.promo_code`.

**`bot_delayed_messages`** — сообщения, которые бот должен отправить
позже: `user_id`, `kind` (сейчас один вид — `promo_prompt`), `due_at`,
`sent_at`.

**`bot_dialog_state`** — новое состояние `awaiting_promo_code`; в
`context_json` лежит `until` — до какого времени бот ждёт промокод.

Код — `src/Partners/PartnerProgram.php` (правила и отчёт) и
`src/Telegram/DelayedMessages.php` (очередь).

## 6. Как работает отложенное сообщение

Засыпать на 10 секунд в обработчике нельзя: бот — один процесс, и пауза
остановила бы его для всех. Поэтому при «Старте» в `bot_delayed_messages`
записывается строка со временем отправки, а цикл бота
(`bin/daemon_telegram_bot.php`) на каждом обороте отправляет то, чему
пришло время, и не ждёт новых сообщений от Telegram дольше, чем осталось
до ближайшей отправки. Отсюда 10–12 секунд вместо ровно десяти.

Строка помечается отправленной до отправки: если отправка сорвётся,
предложение не будет уходить снова и снова — человек введёт промокод
через «Подписку».

Если файлы оказались на сервере раньше миграции 034, бот работает как
прежде: «Старт» — обычный, очередь не трогается, команды администратора
отвечают, что нужна миграция. Наличие таблиц перепроверяется раз в пять
минут, но после миграции бота всё равно нужно запустить заново.

## 7. Что появится вместе с оплатой

Сейчас не сделано и ждёт оплаты:

1. **Размер скидки** — не задан.
2. **Шаг «введи промокод» при оплате.** Перед выставлением счёта:
   `PartnerProgram::canEnterCode($userId)` — можно ли ещё предложить ввод;
   `PartnerProgram::discountCode($userId)` — промокод, по которому
   положена скидка, или `null`.
3. **Отметка первой оплаты.** Код оплаты при первом успешном платеже
   заполняет `users.first_paid_at` (один раз) — с этого момента скидки
   нет. Каждая оплата — строка `payments` со `status = 'succeeded'`,
   `paid_at` и `amount` (сколько клиент заплатил на самом деле, со
   скидкой).
4. **Правило вознаграждения** — подтверждено администратором
   13.10.2026: процент партнёра от суммы всех успешных оплат приведённых
   им клиентов за месяц. Так отчёт и считает; с появлением оплаты менять
   в нём ничего не нужно.

## 8. Отчёт за месяц

По каждому партнёру:

| Показатель | Что это |
|---|---|
| привёл всего | клиенты с `referred_by_user_id` = партнёр |
| по ссылке / ввели сами | они же по `referral_source` |
| привёл за месяц | `referred_at` в этом месяце |
| хоть раз платили | из приведённых — с заполненным `first_paid_at` |
| впервые оплатили за месяц | `first_paid_at` в этом месяце |
| клиентов с оплатой за месяц | у кого есть успешный платёж в этом месяце |
| платежей и сумма за месяц | успешные платежи (`status = 'succeeded'`) с `paid_at` в этом месяце |
| вознаграждение | сумма × `reward_percent` / 100; процент не задан — не считается |

Возвращённый платёж (`refunded`) в сумму не входит. Месяц — по времени,
как оно записано в базе, то есть по часам сервера (UTC, на три часа
позади Москвы): оплата в 01:00 по Москве первого числа попадёт в
предыдущий месяц.

Три способа получить одни и те же числа:

- в боте: `/partners` или `/partners 2026-10`;
- на сервере: `php bin/partner_report.php --month=2026-10` (с `--csv` —
  строки через «;» для таблицы); скрипт только читает базу;
- запросом к базе — ниже. Даты месяца в нём стоят дважды у каждого
  условия: начало месяца и начало следующего.

```sql
SELECT
    pu.telegram_username AS partner,
    pu.telegram_id,
    p.promo_code,
    p.status,
    p.reward_percent,
    (SELECT COUNT(*) FROM users c WHERE c.referred_by_user_id = p.user_id) AS referred_total,
    (SELECT COUNT(*) FROM users c WHERE c.referred_by_user_id = p.user_id
        AND c.referred_at >= '2026-10-01' AND c.referred_at < '2026-11-01') AS referred_in_month,
    (SELECT COUNT(*) FROM users c WHERE c.referred_by_user_id = p.user_id
        AND c.first_paid_at >= '2026-10-01' AND c.first_paid_at < '2026-11-01') AS first_paid_in_month,
    (SELECT COUNT(DISTINCT pay.user_id) FROM payments pay JOIN users c ON c.id = pay.user_id
      WHERE c.referred_by_user_id = p.user_id AND pay.status = 'succeeded'
        AND pay.paid_at >= '2026-10-01' AND pay.paid_at < '2026-11-01') AS paying_clients_in_month,
    (SELECT COUNT(*) FROM payments pay JOIN users c ON c.id = pay.user_id
      WHERE c.referred_by_user_id = p.user_id AND pay.status = 'succeeded'
        AND pay.paid_at >= '2026-10-01' AND pay.paid_at < '2026-11-01') AS payments_in_month,
    (SELECT COALESCE(SUM(pay.amount), 0) FROM payments pay JOIN users c ON c.id = pay.user_id
      WHERE c.referred_by_user_id = p.user_id AND pay.status = 'succeeded'
        AND pay.paid_at >= '2026-10-01' AND pay.paid_at < '2026-11-01') AS amount_in_month
FROM partners p
JOIN users pu ON pu.id = p.user_id
ORDER BY p.created_at, p.user_id;
```

Клиенты одного партнёра (промокод — нынешний код партнёра):

```sql
SELECT c.telegram_id, c.telegram_username, c.used_referral_code, c.referral_source, c.referred_at, c.first_paid_at
FROM users c
JOIN partners p ON p.user_id = c.referred_by_user_id
WHERE p.promo_code = 'IVAN2026'
ORDER BY c.referred_at, c.id;
```

## 9. Тест

```
php -d extension=mbstring -d extension=pdo_sqlite tests/test_partner_program.php   # 55 проверок
```

Весь путь через настоящий обработчик бота: назначение партнёра, ссылка с
промокодом, предложение через 10 секунд, ввод сообщением, кнопка в
«Подписке», правила (один раз, не свой, только до первой оплаты,
приостановка, смена кода), отчёт за месяц с платежами, работа без
миграции 034.

Не проверено офлайн и проверяется на сервере после установки: сама
миграция на MySQL и приход отложенного сообщения в настоящем цикле бота.
